# 短窗（0.5 s）取舍实验 — P0-2

> 一句话结论：**告警延迟能从 1.0 s 砍到 0.5 s，但必须重训；不重训会丢掉 30% 的事件。**
> 代价是段级 acc −3.3 pp / macro-F1 −2.2 pp，事件级命中率保持 100%、误报保持 0。

## 为什么之前那个「0.5 s 掉到 .7192」不能当结论

老代码把 0.5 s 的 50 帧 **补零 pad 回 100 帧**（`mel.waveform_to_logmel` 的
`frames` 是固定常量），模型实际看到的是「半窗信号 + 半窗静音」。用同一份 1 s
权重把这件事量化出来：

| 条件 | 段级 acc | 段级 macro-F1 |
|---|---|---|
| 1.0 s 窗，100 帧（基线） | 0.8636 | 0.8708 |
| 0.5 s 窗 **补零到 100 帧** | **0.4608** | **0.4382** |
| 0.5 s 窗，只取 50 帧（同一份权重，无补零） | 0.8288 | 0.8234 |
| 0.5 s 窗，50 帧，**短窗重训** | 0.8307 | 0.8491 |

所以「短窗必然掉精度」里有一大半是补零造成的假象；真正的代价只有 3 pp 左右。

## 事件级：训练与否在这里才分得出高下

段级数字骗人 —— 0.83 vs 0.86 看起来「差不多」。真正决定产品能不能用的是
事件级（`make demo-e2e`，60 s 真场景，10 个非背景事件，事件 = 2 s 连续同类）：

| 窗长 | 权重 | 事件命中率 | 整段落窗延迟 p50 / p95 | 整段落窗误报 |
|---|---|---|---|---|
| 1.0 s | 1 s 头 | **100%** | 1000 / 2000 ms | 0 |
| 0.5 s | 1 s 头（不重训） | **70%** | 500 / 1500 ms | 4 |
| 0.5 s | **0.5 s 头** | **100%** | **500 / 1500 ms** | **0** |

漏掉的 3 个全是 siren，被判成 background 且置信度 0.78–0.95 —— 也就是
「很自信地听不见」。这类失效在产品上比随机错更危险，也正是短窗必须重训的理由。

## 复现

```bash
export SAFESOUND_DATA_DIR=/root/safesound_data
make train-short05     # 0.5 s 头（帧数 50，不补零），单卡约 6 min
make shortwin          # 段级四行对照 → outputs/reports/short_window_eval.json
make demo-e2e          # 1 s 基线
python3 code/demo_e2e.py --win-s 0.5 --hop-s 0.25 \
    --ckpt outputs/models/dscnn_v2_short05.pt     # 短窗
```

`make demo-e2e` 与短窗命令的 `summary.json` 存在
`outputs/reports/demo/summary_win{1.0,0.5}_ckpt{1s,short05}.json`。

## 口径限制（写论文时必须带上）

1. 段级表是**单窗、段首对齐**的离线评测，与 `detection_numbers.json` 同测试集
   （3533 段 / 137 录音组，prep = raw，4 类头）。流式里窗口落点是随机的，故
   事件级表才是延迟主张的依据。
2. 事件级只有 **10 个事件**（n 太小）：100% vs 70% 就是 3 个 siren 的差别，
   只能当方向性证据，不能当显著性结论。段级表是 3533 段，才是统计上站得住的那一层。
   短窗头也只跑了单 seed（1 s 头是三种子），3 pp 的段级差距落在种子噪声量级以内。
3. 短窗头**没有**重跑 ONNX 量化；导出链路对 `frames` 是参数化的，但要重跑
   `make onnx` 才有 int8 短窗模型。
4. 这些数字属于 4 类部署头，**不可**与 v3 多标签（91.19 / 93.11 / mAP .9113）互相引用。

## 顺带修掉的隐患

检查点的 mel 参数以前靠**文件名里有没有 `fft1024`** 猜。改名或换窗长就会静默
改变输入分布（照样输出 softmax，只是全错）。现在：

* `train_dscnn_v2.py` 把 `mel` 字典写进检查点；
* `vocab.resolve_mel()` 以检查点元数据为准，文件名只作兜底**并告警**；
* `tests/test_mel_provenance.py` 6 条断言锁住（含「元数据覆盖文件名」「frames=50
  不许被档位表吸附回 100」）。
