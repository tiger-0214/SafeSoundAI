# 声音过滤需求与语义规范（filter_spec）

> 本文定义「过滤什么、保留什么、用户怎么改」——即过滤模块的**语义层契约**。
> 上游：AED（`config.TARGET_CLASSES` 10 类，class_id 0–9）
> 下游：触觉编码（E1 user profile）、衰减/分离执行器（A2.2 / A2.3）

## 一、核心原则

过滤器的目标不是「降噪」，而是**在不牺牲安全信息的前提下降低用户的听觉负担**。由此导出一条不可交易的顺序：

```
紧急声白名单  >  用户个性化偏好  >  空间/距离条件  >  舒适度（抑制量）
```

即：任何情况下，只要白名单类被检出且置信度达标，就必须**通透**（默认 0 dB，可选 +3~6 dB 增强）；个性化与空间条件只能在此之后缩小"可抑制集合"，不能覆盖白名单。

## 二、三类语义表（唯一权威定义）

`class_id` 与 `config.TARGET_CLASSES` 一致。**黑名单 = 用户可关，但不可把紧急类放入黑名单**——若用户试图这样做，UI 必须提示且系统降级为"仅舒适抑制"，见 `filter_safety.md` §三。

### 2.1 白名单（WHITELIST —— 永不抑制）

| id | 类别 | 角色 | 默认增益 | 理由 |
|:--:|---|---|:--:|---|
| 8 | siren | 🔴 核心危险 | 0 dB（可 +3） | 交通/救援预警，唯一必须无条件保留的声源 |
| 1 | car_horn | 🔴 核心危险 | 0 dB（可 +3） | 碰撞预警，与 siren 同属强制保留 |
| 6 | gun_shot | 🔴 核心危险 | 0 dB | 瞬态冲击声，需触发触觉但不必增强音量（防惊跳） |
| 3 | dog_bark | 🟡 警示 | 0 dB | 攻击性犬只预警 |

### 2.2 黑名单（BLACKLIST —— 默认抑制，用户可调）

| id | 类别 | 角色 | 默认增益 | 目标抑制 |
|:--:|---|---|:--:|---|
| 0 | air_conditioner | ⚪ 背景 | −12 dB | −12 ~ −20 dB |
| 5 | engine_idling | 🟠 高危 | −6 dB | 弱抑制（保留空间感） |
| 9 | street_music | ⚪ 背景 | −12 dB | −12 dB |
| 7 | jackhammer | 🟠 高危 | −6 dB | 弱抑制（施工区仍需环境意识） |
| 4 | drilling | 🟠 高危 | −6 dB | 同上 |

### 2.3 中性表（NEUTRAL —— 不主动处理）

| id | 类别 | 角色 | 默认增益 | 说明 |
|:--:|---|---|:--:|---|
| 2 | children_playing | 🟡 警示 | 0 dB | 语义双面（干扰 vs 安全），交由用户档位决定 |

### 2.4 用户档位（与 E1 profile 对接）

`profile_id` → 三张表的替换版本，字段结构固定为：

```json
{
  "profile_id": "ptsd_default",
  "whitelist": {"siren": 0, "car_horn": 0, "gun_shot": 0, "dog_bark": 0},
  "blacklist": {"air_conditioner": -12, "street_music": -12, "engine_idling": -6,
                 "jackhammer": -6, "drilling": -6},
  "neutral":   {"children_playing": 0},
  "enhance_whitelist_db": 0,
  "max_total_attenuation_db": 24,
  "fail_open": true
}
```

内置三个预设：

| profile | 白名单 | 黑名单 | 增强 | 适用 |
|---|---|---|---|---|
| `comfort` | 4 类 | 全 5 类，−18 dB | 0 | 日常降噪，最高抑制 |
| `ptsd_default`（默认） | 4 类 | 5 类，−6~−12 dB | 0 | 创伤后应激：压低触发声、绝不屏蔽警报 |
| `awareness` | 4 类 | 仅 2 类背景，−6 dB | +3 | 高环境意识场景（户外步行） |

## 三、增益执行契约

对每个 1 s 分析窗 `t`，AED 输出后验 `p_t(c)`，执行器必须产出**每个时频单元**的增益 `g(t,f)`，满足：

1. **类条件化**：`g` 由"当前生效集合"决定，而非单一 top-1 类别（top-1 抖动会造成增益跳变）。
2. **软混合**：按后验加权合并各类的目标增益，而不是硬选一类：
   ```
   w_c = soft(p_t(c))           # 温度 0.7 的 softmax，压制低置信噪声
   g_db(t,f) = Σ_c w_c · gain_db[c] · M_c(t,f)
   ```
   其中 `M_c(t,f)` 是"该时频单元属于类 c"的软掩码（谐波/能量掩码，见 `filter_arch.md`）。
3. **上下限**：`g_db ∈ [−max_total_attenuation_db, +6]`。
4. **平滑**：跨帧增益做一阶平滑 `α=0.5`，禁止帧间跳变 > 6 dB（避免"呼吸"噪声）。
5. **流式一致性**：谱归一化必须使用 `running mean/var`，禁止逐窗 z-score（逐窗会让同一背景在相邻窗获得不同基准，产生周期性调制；见 `filter_constraints.md` §四）。

## 四、验收判据（与 A2.5 报告对齐）

| 层 | 指标 | 目标 |
|---|---|---|
| 语义 | 白名单类被抑制 > 3 dB 的比例 | **0%** |
| 语义 | 黑名单类实际平均抑制量 | ≥ 12 dB（方案 A）/ ≥ 20 dB（方案 B） |
| 体验 | 端到端延迟（采集→输出） | ≤ 100 ms（理想 ≤ 50 ms） |
| 体验 | PESQ 相对下降（非目标段） | ≤ 0.2 |
| 安全 | 静默压制次数（白名单检出但被压 > 3 dB） | **0** |

## 五、非目标（明确不做）

- 不做语音分离/语音增强（music/人声分离不在范围内，避免与 A3/A4 争夺算力）。
- 不做距离估计（双麦硬件不具备，`HearableSoundBubbles` 的 6 麦条件无法复现）。
- 不做个性化学习（档位为离散枚举，A/B 实验后再考虑连续化）。
